How it works

A last-mile day is a vehicle routing problem with capacities and time windows. Every order lands inside its slot, nothing carries more than it can hold, fleet is limited. Find the cheapest day that does all that.

The search

First pass is regret insertion, so whichever order would hurt most to leave for later goes in first. Then ALNS (ropke & pisinger 2006) keeps ripping chunks of the plan out and putting them back. 4 ways to remove (random, priciest, related groups, whole short routes) and 4 ways to reinsert all compete, whichever finds wins gets picked more. Sometimes it keeps a worse plan on purpose (simulated annealing) so it doesn't get stuck. Every new best gets polished by shuffling single orders between routes and swapping route tails.

Checking time windows fast

Each route tracks the earliest every stop can start and the latest it can start without making something after it late. With those two numbers "does this order fit here?" is O(1) (savelsbergh 1992). That's the whole reason tens of thousands of rebuilds finish in seconds.

Independent check

Before any plan shows up, separate code re-checks it from scratch. Every order once, nobody over capacity, no drop outside its slot, everyone back before the depot closes.

What it does not model

Distances are straight line × road factor, not real roads. No traffic changes through the day (yeah, i know, bengaluru). One vehicle type per plan. Deliveries only, no pickups or returns.

Several trips per rider

A bike does ~20 kg so riders head back to reload a few times a day. The search plans trips, each leaves as late as its slots allow, then trips get handed out so a rider grabs the next one they can make after a 10 min reload. Going in departure order and giving each trip to whoever freed up most recently uses the fewest riders possible for those times.
